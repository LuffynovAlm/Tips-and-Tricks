73 entries + 43 v6Command/Bmad/Bmad commands.md

BMad skills are invoked as slash commands in Claude Code (e.g. /bmad-prd) or by naming them in chat. The [CODE] prefix is the agent menu code shown by bmad-help. Run each workflow in a fresh context window (/clear). Version 6.12.4 (core and bmm 6.12.4 · bmb v2.2.2 · cis v0.3.2 · tea v1.19.0 · wds v0.4.3) — sections tagged {v6.12.4} apply to it; sections tagged {v6} are the previous generation, hidden until you tick "Show v6 (legacy) tips". Most v6 skill names still work as forwarding shims (removal rides the v7 cut).

Hve Commands

39 entriesCommand/Hve/Hve commands.md

microsoft/hve-core (Hypervelocity Engineering) — the RPI loop: Research → Plan → Implement → Review. In Claude Code the phases are skills (/rpi-research …, installed with hve.ps1). In GitHub Copilot (VS Code extension *HVE Core*) they are prompts bound to agents (/task-research …). Every phase writes its artifact under .copilot-tracking/ — that folder, not the chat, is the memory.

Install (Claude Code, from HVE-Core-ClaudeCode)7

./hve.ps1 list
Catalog of installable items, by group
./hve.ps1 add rpi -Target '<project>'
Install every rpi-* skill into the project's .claude/ (quote paths with spaces)
./hve.ps1 add all -Target '<project>'
Install everything (skills, agents, rules)
./hve.ps1 add rpi -Ref v1.0.0 -Target '<project>'
Pin a hve-core branch or tag
./hve.ps1 update -Target '<project>'
Re-sync installed items to the latest hve-core
./hve.ps1 status
What is installed + hve-core commit
./hve.ps1 remove rpi -Target '<project>'
Uninstall (only items in .claude/hve-manifest.json, your own skills are untouched)

TokenCost Tips

16 entriesTips/TokenCost/TokenCost tips.md

Keeping AI usage visible and cheap with Claude Code and GitHub Copilot. The matching commands are in the Claude and GithubCopilot command sheets, under Tokens & Cost.

Always trace the cost7

Put the conversation's cost in the task's results and deliverables
Before you close a task, run /cost (Claude Code) or /usage (Copilot CLI) and paste the numbers into the PR description, the BMad spec or story file (*Implementation Notes* in 6.12.4, *Dev Agent Record* in v6), the commit body or the report. This shows the real cost of each feature and makes estimates better over time
Use one standard trace line
AI usage: Claude Code · Opus 5.5 · effort high · 1.2M in / 85k out tokens · $4.20 · 2 sessions. Use the same format everywhere so it's easy to grep and add up
Record the model and effort with the cost
The same task can cost 5–10× more depending on the model. A cost figure without the model means little
One task = one session
/clear between tasks so the cost you read belongs to exactly one deliverable. BMad already recommends a fresh context per workflow
Add up the cost of multi-session tasks
When a story spans several sessions (create → dev → review), record each session's cost and give the total in the final deliverable
Log cost automatically in CI / scripts
claude -p … --output-format json returns total_cost_usd and usage. Store them next to the build artifacts
Trust the billing page over session counters
The Copilot CLI /usage counter can undercount after compaction. Reconcile monthly with GitHub billing, and with your Anthropic console or /usage for Claude

Spend fewer tokens9

/clear between unrelated tasks
Every message resends the whole context, so old, unrelated history costs you on every turn
/compact <focus> before the context fills
A summary you guided keeps the decisions and drops the noise. Automatic compaction is less selective
Check /context
Find out what is actually using space: large files, long tool outputs, MCP tool definitions
Point at files with @file / #file
Precise context beats letting the agent search and read half the repo
Match the model to the task
Haiku or Sonnet for routine edits, renames and docs. Opus for architecture and hard bugs. /effort low when no deep reasoning is needed
Disable unused MCP servers
Each connected server adds its tool definitions to every request
Keep CLAUDE.md / copilot-instructions.md short
They are loaded on every request, so each extra line is paid many times
Set a budget cap
claude --max-budget-usd 5 stops a runaway agent loop before it gets expensive
Write precise prompts
A precise first prompt avoids several correction rounds, and each of those rounds resends the full context

HVE RPI — rpi-review and friends11

One RPI phase per session
Research, plan, implement, review each write a file in .copilot-tracking/. /clear between phases: the next phase reads the file, not the chat, so you pay for less context
Always close with /rpi-review
It compares plan vs changes and writes RV-xxx findings with a route: defect → /rpi-implement, missing decision → /rpi-plan, missing evidence → /rpi-research, extra work → follow-up
Give /rpi-review explicit paths
/rpi-review plan=<plan.md> changes=<changes.md> — it stops if several unrelated tasks match
depth=deep only on purpose
Standard is the default and fast. Deep is never inferred from size or risk: ask /rpi-review depth=deep for critical changes only
Review is resumable
An interrupted review (started) continues from its record. A finished review is reused unless you ask for a new one (-review-2.md)
Answer findings one by one
In manual mode it asks per finding: *use suggested action*, *gather more info*, *skip*, *finish*. Skipped material findings block a conformant outcome — on purpose
Critique the plan before coding
/rpi-plan runs a standard critique by default; /rpi-plan-critique plan=<file> for an independent second look. Fixing a plan is cheaper than fixing code
Challenge a decision
/rpi-challenger subject=... asks one skeptical question per turn, no answers given — good before an architecture choice
Understand a change
/rpi-walkthrough target=<files> detail=brief explains segment by segment with file links
Copilot equivalent
/task-research, /task-plan, /task-implement phaseStop=true, /task-review scope=today, or /rpi task=... for the autonomous RPI Agent
BMad or RPI?
BMad spec / story → /bmad-code-review. RPI-tracked task (plan + changes in .copilot-tracking/) → /rpi-review. Each review expects its own artifacts
